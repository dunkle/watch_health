# 可选的少量免费 AI 额度网关

这是可部署的最小服务端实现，**仓库没有已部署的免费服务，也没有内置平台密钥或已激活额度**。运营者需要承担模型费用、部署 HTTPS 服务，并向每个用户单独发放可撤销的访问令牌。当前不包含注册、登录、购买或 App Store 交易验签。

App 可以通过“兼容接口”配置此网关：API 基地址 `https://你的域名/v1`、运营者指定模型名、该用户的访问令牌。它接受 OpenAI 形式的 `POST /v1/chat/completions`。请求仅包含用户在 App 中确认的选定文字和身体数据，不传原始声音。服务端不应替用户默认授权发送健康数据。

## 部署前配置

Python 3.10+，仅使用标准库。以单独的非 root 服务用户运行，把密钥放在权限 `0600` 的服务环境文件或平台 secret 管理中；不要放进 App、Git、Shell 历史或客户端可下载配置。

必须设置以下环境变量：

| 变量 | 内容 |
|---|---|
| `WATCHMIND_UPSTREAM_URL` | 固定 HTTPS Chat Completions 完整地址，结尾 `/chat/completions` |
| `WATCHMIND_UPSTREAM_KEY` | 服务端自己的上游 API key |
| `WATCHMIND_MODEL` | 单个允许的模型名，App 中填写相同名字 |
| `WATCHMIND_CLIENT_TOKENS_JSON` | JSON 对象：每个随机强令牌映射一个不含身份信息的账号 ID；例如 `{"用户令牌":"account_随机ID"}`；令牌最少24个字符，建议用 `secrets.token_urlsafe(32)` 独立生成 |
| `WATCHMIND_QUOTA_DB` | 持久化 SQLite 文件的绝对路径；目录仅服务用户可访问 |
| `WATCHMIND_DAILY_LIMIT` | 每个账号每日成功结果数量，默认3，1—1000 |
| `WATCHMIND_DAILY_ATTEMPT_LIMIT` | 每个账号每日最多上游尝试数，默认与成功额度相同，1—10000；失败 / 超时 / 无效结果不返还此预算 |
| `WATCHMIND_ACCOUNT_RATE_LIMIT` | 每个账号滚动60秒最多接受的上游尝试数，默认3，1—1000；跨UTC午夜不重置 |
| `WATCHMIND_GLOBAL_DAILY_ATTEMPT_LIMIT` | 全服务共享数据库的UTC每日最多上游尝试数，默认1000，1—1000000 |
| `WATCHMIND_BREAKER_FAILURE_LIMIT` | 连续上游错误 / 超时 / 无效响应的熔断门槛，默认5，1—1000 |
| `WATCHMIND_BREAKER_COOLDOWN_SECONDS` | 熔断阻止新上游请求的秒数，默认60，1—3600；状态持久化，重启不绕过 |
| `WATCHMIND_MAX_INFLIGHT` | 进程最多同时处理请求数，默认8，1—64 |
| `WATCHMIND_PORT` | 本机 HTTP 端口，默认8088 |

同一用户可配置多个令牌映射到同一个账号，额度仍共享。撤销或轮换时更新 secret 并重启服务。令牌表当前上限1000项，适合受控内测；公开注册应迁移到正式身份系统。

```sh
python3 server/gateway.py
```

服务只监听 `127.0.0.1`。在前面部署可信反向代理，终止 HTTPS，限制请求体128KiB，设置连接/请求读取超时、每个账号及来源 IP 的速率限制，并限制头部大小。关闭请求体、Authorization、响应体的代理日志和 APM 内容采集；普通基础设施访问日志也要在隐私说明中交代及设保留期。客户端 HTTPS 不可跳过证书验证。

上游地址由运营者固定配置，客户端不能修改地址、切换模型或增加工具调用等字段。服务拒绝上游重定向，避免向别处转发 API key。应用层处理最多64条消息、28000个总输入字符（App 证据最多24000字符，另预留系统提示空间）、2000个输出 token，请求/响应各128KiB，最终文字上限12000字符。上游 I/O 单次超时10秒，总读取期限45秒（最后一次阻塞最多再10秒）；没有自动重试。务必为上游账号设置费用上限和报警。

## 额度与数据

- 成功额度、每账号尝试预算和全局尝试预算按UTC自然日计算；账号速率按滚动60秒计算。SQLite `BEGIN IMMEDIATE` 将所有检查与预留放在一个原子事务中，限额在调用上游前生效。
- 每个通过校验并获准的请求先扣一次**尝试预算**。即使返回无效内容、超时、供应商拒绝或客户端断开，也不返还尝试预算。只有成功结果占用“成功额度”；失败仅返还成功额度，不会把已执行过的付费尝试抹掉。运营者可显式把尝试预算设得比成功额度大，未配置时默认相同，避免重试无限支出。
- 默认每账号每日最多3个成功结果且最多3次上游尝试，因此失败后当天可能无剩余尝试，即使成功结果尚不足3个。App应显示接口返回的429并由用户明确决定稍后重试；不暗中自动重试。两个预算并不保证每用户一定获得3个成功结果。
- 连续错误达到门槛打开服务级熔断，返回503且不调用上游。状态持久化；冷却后允许恢复，成功清除闭合状态的连续错误数。较早的在途成功不能提前关闭已打开熔断。并发在途请求仍可能产生费用，最坏次数另受全局预算约束。
- 已执行请求的次数不是货币费用估算；每次模型上下文 / token价格不同。还必须在模型供应商账户设置硬费用上限和报警，并在代理设置IP / 连接限流。此代码不声称能够核实供应商实际账单或取代付款侧费用上限。
- 进程崩溃造成的reserved记录保守占用成功及尝试额度直到UTC当天结束；不自动重试。重启、换令牌（映射相同账号）、失败退款和并发不能重置已用尝试。旧数据库自动增加时间列，旧reserved / complete记录仍计为已用尝试；无法恢复旧版本已经删除的失败历史，升级应选择受控窗口并设置供应商费用上限。
- SQLite只保存随机请求ID、账号ID的SHA-256、UTC日期、接受时间戳、状态和一个服务熔断计数 / 截止时间，不保存正文、健康数据、模型输出、原始账号ID、客户端令牌或上游密钥。超过30天的请求记录在下一次预留时移除；熔断状态只有常数一行。
- 数据仍经服务端内存和上游模型处理，上游的保留、训练、地区政策需在对客隐私说明中明确。没有“零云处理”的承诺。
- SQLite 文件0600，服务 `umask 077`。磁盘/快照/系统备份的加密和保留由部署方配置，文件权限不替代加密。同主机多进程必须共用同一个可靠本地SQLite和一致配置；不要用独立SQLite或不可靠网络挂载实现共享限额。跨主机多实例应迁移到支持事务的共享服务数据库，并保留全局配额 / 熔断语义。
- 返回的 AI 内容仍属不可信的推测。该网关不诊断疾病，也不验证情绪/意图准确性。

## 验证与上线范围

```sh
python3 -m unittest discover -s server -v
```

测试使用回环 HTTP 和替身上游，不调用公开模型、不花费额度。覆盖认证和令牌撤销、输入 / 输出界限、成功额度退款与尝试不退款、失败 / 无效输出 / 超时、并发账号及全局预算、跨UTC午夜滚动速率、持久熔断及恢复、旧库迁移 / 保守崩溃、固定模型、错误净化、重定向禁止。`GET /health` 只返回服务存活，不证明上游付费账号或业务可用。

上线仍需要真实 HTTPS/上游联调、正式身份与令牌发放/找回、监控告警、代理IP及来源防护、压力与恢复测试、隐私政策/用户同意、模型供应商协议和费用预算；本实现没有宣称这些已经完成。下载与执行端侧模型由 App 的推理引擎负责，此网关不提供模型下载。
