## 2. 两款产品的定位与边界

| --- | --- | --- | --- |

## 5. 融合后的页面流程（P）

保留现有四个主入口，先改善日常主流程，人物管理作为记录内的二级入口，避免立即增加多个主Tab。

1. **现在**：虚拟人物 + 新鲜健康状态 + 开启 / 结束观察；录音时可主动「标记此刻」，顶部显示实际录制 / 暂停状态。
2. **记录**：日期选择 + 心率曲线 + 小时导航；同一会话跨小时显示持续标识，点击事件进入统一详情。之后逐步加入搜索、收藏、标签和人物筛选。
3. **详情**：事件时间、触发 / 人工标记原因、本人感受、附近原话、实际片段播放、完整转写、健康快照。高光必须能跳到这个证据位置。
4. **每日回顾**：先列事实与已有摘要，再呈现已核对高光；可选一个反思问题，允许跳过、纠正。记录不足时明确不足。
5. **设置**：保留形象、语言、时长、权限、数据管理；新增处理中心入口，未来记忆管理另列可查看 / 编辑 / 停用界面。

## 6. 融合需求与验收（设计与交付状态）

功能编号从F21继续。F21–F23已完成本版代码与自动化检查，原生界面和真机仍待验收；F24–F28为规划。下面的P0 / P1 / P2保留相对顺序，不代表所有能力已经完成。

| 编号 / 顺序 | 功能、依据 | 数据与实现要点 | 验收条件 |
| --- | --- | --- | --- |
| F21 / 已实现 | 录音中人工标记；R03 | 保存标记时间、来源、会话ID、可选备注；复用实际音频片段索引，不能伪装为心率触发 | 不重复开麦；断点空档显示无音频；跨日保留；所有者删除时清理；模拟标记与真实分离 |
| F22 / 已实现 | 处理中心；R04–R05 | 分开显示已录制、传输（仅真实存在的数据类型）、转写、摘要；失败任务能定位原因与重试 | 未实现Watch音频前不显示其同步量；真实进度；重复重试仅一任务；退出重进状态可解释 |
| F23 / 已实现 | 小时导航与跨小时事件；R06 | 以时间范围查询现有事件，持久化使用绝对时间，显示用本地日历；不复制或裁切原文件 | 整点、跨午夜、夏令时、改变时区和中断缺口不丢记录；同一会话各入口定位同一原文件 |
| F24 / P1 | 高光、收藏、证据卡；R07 | 独立保存来源片段、文本范围、生成方式、用户确认；可撤销，不覆盖原转写 | 每条高光有可点击证据；来源删除后同步清理；不将未入选当成不重要；AI失败仍可人工收藏 |
| F25 / P1 | 本地全文检索；R02 | 首先搜索转写与用户备注，之后支持标签 / 人物；索引包含来源与时间定位 | 离线中英搜索、无结果、删除后索引清理、模拟隔离；只对确实录下的文字定位；不为检索外发档案 |
| F26 / P1 | 每日事实 + 可选反思；R08 | 与原摘要分区；由当天证据生成有限开放问题，规则模板可降级；本人回答独立保存 | 不伪造未确认感受 / 原因；可跳过；无数据不套用结论；切换语言不改写原始回答 |
| F27 / P2 | 可管理长期记忆；R09 | 建议记忆与本人确认分开，保存来源、版本、启用状态；关闭记忆后基础回顾继续可用 | 可看、改、停用、删除；来源撤回后失效或重核；不能因一次心率波动形成永久人格标签 |
| F28 / P2 | 人物与对话整理；R02 | 先允许手动人物昵称 / 关联，后评估端侧说话人分离；局部说话人编号与跨录音身份分别表示 | 本人可修正；无证据保留未知；不从声纹猜真实姓名；删除人物不误删整个共享会话；跨语言 / 多人准确率需实测 |

Watch直接录音、真实断连音频队列、独立同步与长时间后台行为属于F04的后续扩展：先做WatchKit音频、存储、电量和配对传输技术验证，再给出产品承诺。不会仅凭竞品宣传修改当前手机录音前提。

## 7. 数据与AI边界

- 现有Trigger不应承载所有新标记：人工标记需有独立来源与时间，心率值不存在时不填假数值，心率事件显著度不套到人工事件。
- 所有新对象共享会话 / 实际片段索引；恢复造成的空档不得压缩。跨小时导航、高光、搜索和反思引用都使用同一证据地址。
- 本地索引、人物、记忆应纳入文件保护、导出 / 恢复及删除传播设计；落地前明确档案迁移，不能只存进UI临时状态。
- 人物只提供场景组织，不建立关系好坏排行榜；身体状态、本人感受和待验证解释继续分开。
- 暂不照搬“高效 / 高精度”选项：当前Apple本地识别接口没有同义的可控双模式。引入第二个模型前验证包体、下载、设备支持、语言、温度、速度和耗电。
- 不接入竞品使用的远程转写 / DeepSeek / 用户API凭据。本轮保持已有规则与Apple端侧摘要路线；如未来增加云端，应另行明确所发数据和用户单独开启机制。

## 8. 分批交付与review

第一批F21–F23：让用户能标记、看清处理阶段、按小时找回同一事件。先验证新旧档案迁移、断连 / 重试、跨小时 / 空档和真实文件定位。

第二批F24–F26：让记录容易找、摘要有证据、反思可纠正。验收离线检索、删除传播、模型失败降级与本人输入保留。

第三批F27–F28：加入长期记忆与人物管理，先手动整理，再评估模型自动建议；跨录音人物识别和长期推断必须有额外准确率与隐私验证。

每批代码同步更新统一功能文档、验证记录和真机计划。调研初稿只完善设计；当前第一批F21–F23已有实现，F24–F28尚未实现。各阶段的真实验证范围见Validation.md，不能用核心测试代替Apple平台验收。
