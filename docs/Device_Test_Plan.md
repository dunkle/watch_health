# 真机运行与验收

## 安装

设备信息来自用户：M3 Pro Mac、iPhone（用户描述为18PM）、Watch（用户描述系统为12），均为最新系统。实际型号、完整 OS build、Mac 的 macOS、Xcode SDK 和开发者账号能力仍需在设备上核对；不要据此假定模型或后台能力。

1. 在 Mac 上安装兼容的完整 Xcode，打开一次，接受许可并安装 iOS/watchOS 平台和配对设备支持。
2. 克隆仓库，运行 `./scripts/setup-mac.sh`。XcodeGen 配置会生成工程和 Info.plist/entitlements；生成文件不需要手工修改。
3. 打开 `WatchMind.xcodeproj`，在 Signing & Capabilities 中为两个 target 选择自己的 Team。将 iOS bundle ID 改成唯一值，如 `com.yourname.watchmind`；Watch ID 改成其子 ID，并同时更新 `WKCompanionAppBundleIdentifier`。建议直接修改 `project.yml` 后重新生成，让设置可重复。
4. iPhone 与 Watch 开启所需开发者模式并配对。选择 iPhone 真机运行手机 app，再选择配对 Watch 运行手表 target。
5. 若需要 Apple 端侧大模型，使用包含 FoundationModels 的 Xcode 26+ SDK，并在真机检查 Apple Intelligence 可用性。用较旧 SDK 编译时不包含该代码，规则摘要仍可用。
6. 无需 API Key、后端、账号服务或第三方包。签名账号是否允许所需 HealthKit 能力，以实际 provisioning 为准；不要求在聊天中提供密钥。

## 演示与真实模式必须分开

手机“现在→查看模拟记录”可以演示完整页面、文字线索、本人确认和规则摘要。所有模拟数据有明确标识，不播放不存在的录音，也不计入真实记录。退出演示后才可开启传感器观察。

## 真实闭环

- 手机“开启观察”，阅读并同意本次录音行为，允许麦克风、语音识别、健康读取。
- 手机保持前台、屏幕可见，放在能听清本人讲话的位置，确保周围人知情。
- 自然步行时可在 Watch 开始“步行观察”。不应为了触发而过度运动、憋气或制造异常心率；正常使用中没有触发也是有效结果。
- 等待至少5个新鲜样本建立短期基线。遇到自然波动，手机出现录音条；说一段同意被记录的话，手动停止或等待30秒。
- 检查录音、转写和分段、原始音频播放；标记本人感受，再生成每日摘要并核对证据。
- Watch 结束并保存步行，手机结束观察。此后心率变化不应再录音。

## 必测表

填写每项的设备、OS/Xcode版本、时间、预期、实际和通过/失败；未执行不能标为通过。

| 场景 | 预期 |
| --- | --- |
| 权限拒绝、撤销 | 无崩溃，不录音，明确失败 |
| 无健康数据/稀疏样本 | 显示等待，不编造心率或情绪 |
| Watch断连/延迟事件 | 旧事件不补录，不冒充捕获当时语音 |
| 两路同一事件 | 冷却窗口内不重复录音 |
| 前台自然波动 | 按本次设置上限录音，本地转写，分段时间正确 |
| 波动前讲话 | 不出现未录到的前文 |
| 锁屏/切后台/来电 | 暂停、保留实际片段；前台解锁且系统允许时尝试恢复，不能绕过时限 |
| 飞行模式 | 已有记录查看和规则摘要可用；本地语音模型缺失时明确失败 |
| 不支持端侧模型 | 使用标注的规则摘要，不发送云请求 |
| AI模型失败 | 报错，可主动选择规则摘要，不丢失记录 |
| 强制终止/重启 | 不自动恢复录音；未完成任务标为中断，可手动重试 |
| 音频/记录删除 | 本机文件消失；健康中的源数据仍在 |
| 存储错误/损坏档案 | 不覆盖损坏文件，不继续采集 |
| 模拟模式 | 明确模拟标识，不计入真实数据 |
| 摘要期间记录变化 | 旧证据生成的结果丢弃，要求重新生成 |
| 功耗与容量 | 比较真实步行会话和普通待机，记录小时级电量、音频增长量 |

## 当前尚未提供

全天可靠的后台录音、Watch 端录音、云端 AI、备份恢复、情绪医学识别、Apple官方睡眠评分、远程真机连接和自动安装。当前云机器无法验证 Apple SDK、签名、硬件或设备上的模型就绪状态。


## 复查修复的重点回归

- 录音期间来电：顶部变为暂停并保留任务占用；符合条件后可恢复为新片段，手动结束后占用必须释放，不依赖录音完成 delegate。
- 连续点两次重试：只有一个转写任务；模拟旧任务结束回调时不得结束或覆盖新任务。
- 授权弹窗期间结束观察或进入模拟模式：授权返回后不能恢复观察，退出模拟也不能自动录音。
- 手表点击结束后：保存期间只显示等待，不允许新建运动；旧 session 的回调不能清空新 session。
- 锁屏期间收到事件或转写完成：文件保护仍为 complete，待保存状态保留内存；解锁后重试，不永久禁用采集。锁屏期间进程被终止，尚未写盘的数据可能丢失，不能承诺已保存。
- 冷启动时保护数据不可读：等待解锁再加载，不把读取失败当空库。磁盘满和损坏档案仍应报错并停止写入。
- 文本“不开心”“没有压力”“unhappy”“not happy”不产生相反的肯定线索；复杂否定、讽刺仍不支持可靠判断。


## 双语与构建进度回归

- 手机设置选择 English：四页、弹窗、记录状态和感受标签切为英文，重启后保留。
- 切回简体中文、选择跟随系统，核对中文/英文系统偏好与其他语言的英文回退。
- 核对长英文按钮、最大辅助字号和 Watch 小屏，不应截断重要的授权说明与停止按钮。
- 手机更改语言后连接 Watch，确认可收到语言偏好；Watch 独立选择可能在手机下一次同步时被覆盖。
- 分别用中文/英文新建自然触发录音，验证 zh-CN/en-US 本地识别；缺少离线能力时不上传。
- 切换语言后重试旧录音，仍使用录制时的语言；旧版无语言字段的录音按原来中文识别。
- 摘要在当前语言生成，切换后不冒充已有另一语言的摘要；原始转写不翻译、不修改。
- 在系统设置切换 App 语言并请求尚未请求的权限，检查 InfoPlist 双语说明；应用内语言切换不改变系统已选的权限弹窗语言。
- 安装脚本核对5个阶段、耗时与长任务15秒心跳。测试或原生编译失败必须保留非零退出码，不能显示最终成功。


## v0.4 长录音与多指标回归

先在模拟模式查看实际示例曲线、橙色重要点和指标页；它们明确为模拟数据，无音频文件。

真机按序验证：

1. 设置录音上限为1分钟，确认默认值初始为60分钟、重启设置保留。自然触发后观察进度条、主动停止与到时停止。
2. 用短录音验证播放、分段转写、时间偏移，再测试跨45秒边界的90秒音频，最后才进行完整1小时试验；记录文件时长、大小、耗电、温度与各段成功率。
3. 不故意制造异常心率；验证自然小幅变化可触发，随后大幅变化即使在小幅检测冷却中也生成重要标记，录音文件始终只有一份。
4. 点击录制中的点：明确尚在录制；录音结束后可按偏移播放，转写结束后显示对应窗口文字。验证部分失败计数与重试。
5. 跨午夜录音：次日标记仍能找到前一日文件，摘要只用对应窗口。删除单个标记不删共享文件，删除文件所有者同时清除关联标记。
6. 逐项授权新HealthKit类型。比对健康App中同一来源、时间和单位；特别核对血氧比例到百分数、HRV毫秒、腕温摄氏度和音暴露dBA。
7. 撤销部分权限或使用无对应硬件的设备，检查未知/过期不变成0、不作为实时信号。音暴露没有数据时不启动额外麦克风监听。
8. 核对睡眠跨午夜、重复来源、仅在床、午睡和清醒重叠，确认“本地估算”标签与8小时目标；不得标成Apple官方分数。
9. 保持屏幕唤醒开/关、手动锁屏、来电与切后台分别回归；不允许因为上限改为1小时就绕过中断或隐藏录音状态。
10. 测试旧档案迁移、曲线数据超过7天/60000点的清理、强制终止后临时音频片段清理、磁盘不足和长任务重试。

以上尚未在用户设备执行。短音频通过不能替代整小时的真实验收；模拟器无法证明传感器持续采样、真实运动情境或离线模型就绪状态。


## v0.5 虚拟人物、恢复与24小时验收（尚待真机执行）

当前行为以 [统一功能文档](FUNCTIONAL_SPEC.md) 为准。测试不要通过制造异常心率触发。

1. **形象**：在首页进入定制，修改20字符内名字及每种外观，查看首页 / 回顾页 / 设置同步变化；重启、恢复默认与中英文切换。清除音频记录不应意外清除形象设置。
2. **时长**：全新安装默认60分钟；预设24小时显示1440分钟，自定义1分钟、23小时59分钟、24小时0分钟；不能出现0分钟或超过24小时。观察期间禁止修改，重启保留。
3. **先短后长**：先设置2–3分钟观察自然触发；录音途中接电话，确认暂停、麦克风释放。挂断回到应用后系统许可时只产生一个续录片段，本次截止时间不变。
4. **条件顺序**：分别测试来电→失去前台、先后台→来电、通话结束仍留在其他 App、锁屏→解锁但不回 App；不能在后台或保护数据不可读时开新片段。
5. **手动恢复**：系统不给 shouldResume 或激活失败时暂停不循环重试；「继续录音」可再次尝试，「结束并转写」释放占用。挂断通知缺失时，手动继续由实际音频激活结果决定，不能伪装成功。
6. **音频路由**：音乐播放、停止、其他独占音频、耳机拔出 / 蓝牙断开、系统音频服务重置。音乐共存是否成功以真机为准；设备断开后需手动继续，后来的系统结束通知不能解除这个要求。
7. **空档对齐**：开始说“A”，中断约30秒，恢复说“B”；B的文字偏移应包含中断等待。B附近标记播放新文件的相应位置，落在通话空档的标记必须显示无对应音频，不跳到B。详情可分别播放真实片段。
8. **结束与超时**：分别在录制和暂停期间结束，确认只结束一次、不再续录；暂停直到时限后回应用，必须结束并处理已录部分，不能重新获得完整时长。
9. **任务与文件**：反复来电、停止、重试、查看详情；不重复开麦，旧片段回调不结束新片段。删除所有者删除每个文件及所有标记；只删标记不删任何共享片段。
10. **持久化与异常**：重启读取旧单文件档案；多片段录制 / 暂停 / 转写时杀进程后，启动不得自动录音，已存部分仍可手动转写；磁盘满、保护数据锁定不覆盖原文件。
11. **长时间验证**：短任务通过后先1小时，再逐步测试4 / 8 / 24小时，记录实际时间与空档、空间、电量、温度、转写耗时 / 成功率。24小时约0.7GB仅是原音频估算；不得用修改系统时间代替真实长测，也不得由1小时通过声称24小时稳定。

模拟器可验证人物、设置和一般布局；真实麦克风中断、音乐 / 电话音频路由、锁屏保护、HealthKit传感器与长期功耗必须使用真机。
