## 3. 采样覆盖率的具体含义

以下只是按S10参数的理想化计算，假设调度准时、每次都成功录到6秒：

- 6秒 / 600秒 = **1%音频时间覆盖率**。
- 开启16小时，约96次采样，共576秒，即 **9.6分钟**；未采样时间约15小时50.4分钟。
- 不是所有模式的覆盖率，也不是成功转写率、语音占比或日记准确率。系统调度、权限和设备状态还可能降低实际采集量。
- 恰好落在两次采样之间的两分钟对话可能完全缺失。声音检测只能筛选已采到的内容，无法找回没有开启麦克风时的声音。

WatchMind目前也有自身覆盖偏差：优先记录心率候选之后的声音，平静、低波动场景可能没有语音；无预录，事件之前的谈话不可恢复。不能据几条心率事件推断“这就是用户完整的一天”，也不能把沉默或没有数据解释为平静。

## 4. 三款产品融合后的产品结构

| 借鉴来源（转述） | 主要价值 | WatchMind融合落点 | 本次决策 |
| --- | --- | --- | --- |
| Auday | 时间、原话、高光、反思、长期记忆 | F21–F27：时间锚点、小时导航、证据与记忆 | F21–F23已实现；继续保留F24–F27路线 |
| 时录 | 对话整理、人物与检索 | F25、F28：全文检索、可修正人物 | 优先手动整理；自动说话人能力另测 |
| Soundiary | 声音筛选、采样预算、原音频控制、少输入日记 | F29–F32：质量、保留、覆盖与资源预算 | 新增待实现需求，不照搬其定时承诺 |
| WatchMind已有方向 | 心率 / 多指标情境、虚拟人物、中英与端侧 | 身体变化 → 实际片段 → 本人确认 → 可核对回顾 | 心率候选仍是自动开麦前提，人物表情不表达未经确认的情绪 |

建议统一产品目标：**用少量、有来源的身体与生活片段帮助本人回顾，公开数据缺口，逐渐积累可修正的个人记录。**

## 5. 新增融合功能（全部为规划）

### F29：录后语音筛选与质量反馈

先处理已授权、已触发并录下的文件，再评估实时检测；这不需要增加触发前监听，也不把周期采样塞进现有心率触发流程。

- 对短窗计算可解释的语音活动 / 质量结果，按原文件时间范围保存：可能有语音、低能量、噪声较多、未知。单纯音量阈值不能可靠区分人声与噪声，需比较本地VAD候选实现。
- 在技术验证后提供五档检测灵敏度，解释为“更易保留轻声 ↔ 更严格过滤”；参数只影响语音候选，不改现有5bpm且5%的心率触发。
- 不确定时保留处理机会；第一版不自动删除低质量原音频。手动标记附近即使被判为安静，也可主动尝试转写。
- 跳过区间保留原始偏移，不把几个有声片段压成假的连续谈话。UI区分“疑似安静”“识别失败”“未录制”“已清理”。
- 录后筛选可能减少转写工作量，但不会减少已经录音消耗的电量或原文件大小；存储优化依赖F30，实际收益需测量。

验收：中文 / 英文、轻声、多人、电视 / 音乐、风噪与耳机环境；各档漏检与误检率；人工标记兜底；时间偏移和失败重试；不支持模型 / 无数据时保留未知。不声明已达到Soundiary的算法效果。

### F30：可选的原音频清理策略

保留现有默认“原音频由用户主动删除”。新增选项建议命名为 **“完整转写成功后清理原音频”**，用户明确开启并说明后仅应用于新会话；既有录音不追溯清理。

- 即使开启此项，录制与转写仍需要本地音频暂存；不能宣传“从未产生音频文件”。
- 仅当全部应处理片段成功、完整转写与时间索引已经可靠写盘、无正在播放 / 转写占用后，才进入可恢复的清理流程。部分失败、中断或档案不可写时保留原音频与解释。
- 会话开始时固定本次策略，途中切换不造成正在使用的文件突然消失。具体过期天数或定时清理默认值尚未确定，不擅自设置。
- 删除音频和删除记录分开。文字、标记、健康快照可留存；事件详情明确“原音频已按所选策略清理”，不能报成“录音中断空档”。清理后不可播放、不可重新识别，应在选择前说明。
- 数据设计需要持久化音频可用状态（保留 / 策略清理 / 用户移除 / 意外缺失 / 未知）与清理日志；录制空档独立表示。原始来源索引可保留，文件入口需禁止误用。
- 清理先写待办状态，逐文件处理并记录结果；异常重启可核对继续，不能将“删除成功、档案未写”误判为未知丢失。此流程尚未实现，不能直接调用现有整条记录删除代替。

验收：部分成功与全失败不清理；磁盘满、锁屏、重启、多文件半途失败、播放占用、跨日标记、高光 / 检索引用、旧档案默认保留、同意撤回对后续会话生效。文字本身仍是敏感记录，清理声音不等于清空个人资料，也不承诺闪存物理安全擦除。

### F31：覆盖情况与有证据的每日回顾

把“采集少时说得少”变成明确的产品行为，扩展F22处理中心与F26每日回顾。

- 规划保存观察会话、实际录音片段、转写成功 / 失败 / 跳过的时间范围及原因。已有档案缺少观察区间或成功转写范围时标未知，不能倒推并补造。
- 分别展示观察开启时长、实际录音时长、成功处理范围和缺失原因；先定义分母再显示比例。去重、裁剪当日区间；共享标记不重复计时，暂停与跨日分摊按绝对时间计算。
- 观察开启也不保证有健康样本；录音时长不等于有语音时长，成功转写区间不等于文字准确度或生活代表性。
- 每日回顾标明记录来自哪些时间与事件，缺失提示包括心率未触发、未佩戴 / 未同步、权限不足、中断、筛选跳过、转写失败等已知情况；不确定原因保持未知。
- 内容按事实、本人表达、待验证线索、可选反思分区。未完成事项仅在实际原话中有明确行动时生成候选，由本人确认，不把模型猜测自动写成任务。
- 没有记录时显示无可用证据；稀疏记录形成“当天片段回顾”，不补全其余生活。具体“稀疏”量化阈值待验证，不能用1%时间覆盖推断准确率。

验收：空白日、短事件、整天观察但无触发、跨午夜 / 夏令时、多标记共享音频、部分识别失败、人工修正、音频清理后文字仍在；覆盖提示与AI输入一致，支持规则降级。

### F32：资源预算与省电策略

- 第一阶段先测量和提示录音大小、处理任务与设备状态，帮助用户选择已有时长上限；展示预估值与实测值的区别。
- 之后评估本地转写按充电、电量、温度等条件延后执行；手动恢复、截止时间和已录片段保护需统一调度。系统不允许执行时显示等待，不伪装固定周期作业。
- 当前1小时默认 / 24小时上限继续有效。新增预算不得暗中缩短用户选择的本次时限；如未来提供“资源不足时提前结束”，应是另一个明确选项并显示实际结束原因。
- “每10分钟采6秒”只作为技术实验候选；当前没有实现Watch录音、音频同步或周期采样，不能承诺watchOS准时唤醒或后台开麦。
- 健康指标可请求已有数据，不等于能强制设备每5分钟测量；新鲜度继续按样本时间检查。

验收：前台 / 后台、低电量、充电、发热、空间不足、任务延后、进程终止、电量与温度恢复、真机长期运行。不同硬件与环境实测比较，不凭采样比例宣称固定倍数续航提升。

## 7. 推荐实现顺序与取舍

1. **F31最小版随F24–F26做**：让高光、检索、每日片段回顾保留证据和缺口；先补真实区间数据，再显示数值覆盖率。原有第二批不推倒重做。
2. **F30进入下一轮P1**：先完善多片段转写与持久进度，再增加用户明确开启的清理策略。它直接影响存储和证据保留，先做迁移与失败恢复设计。
3. **F29先技术验证、再P1实现**：测轻声漏检、噪声误检和耗电，证明确有收益后开放五档控制。首版录后筛选，避免增加后台持续监听。
4. **F27–F28继续P2**：长期记忆与人物先手动确认；采样片段不足时，不自动拼成完整人物关系与整天经历。
5. **F32与Watch独立录音 / 周期采样继续P2验证**：通过实际设备实验再决定是否加入“片段采样模式”。它应是独立、明确选择的模式，不能替换用户既定的心率触发。

本次交付为可审阅设计与验收条目；F29–F32尚无实现。现有默认音频保留、心率触发、1小时默认与24小时上限均未改变。
