# WatchMind 功能文档（持续维护）

版本：v0.5 · 更新日期：2026-10-27（北京时间）。

本文是当前全部功能的统一 review 入口。代码变更应在同一提交更新对应功能、验收条件和限制；旧 PRD 保留为历史，不作为当前行为依据。功能编号用于后续讨论、缺陷定位和优化。实现状态不等同于已通过 Apple 真机验收。

## 1. 产品目标与实现范围

以 Apple Watch / iPhone 的授权健康数据发现值得回顾的身体变化，条件满足时记录之后的声音，在设备本地转写；结合本人反馈和事件附近文字生成每日回顾。手机负责档案、音频、分析和展示，Watch 提供真实步行会话中的心率与提示。无需后端、账号或 API Key；没有云端回退。

心率与其他身体指标只提供线索，不能证明情绪、疾病或因果。虚拟人物用于陪伴展示，表情不作为推测用户心情的输出。

## 3. 虚拟人物 F02

- 展示在「现在」、每日回顾页及设置入口。首页可直接进入定制。
- 名称最多20个字符；三种发型、四种发色、四种肤色、四种服装颜色，配饰为无 / 眼镜 / 耳机。
- SwiftUI 本地绘制，不上传照片，不调用生成模型；目前未提供照片上传、3D、捏脸或动画角色引擎。
- 配置写入本机偏好，重启保留；「恢复默认形象」重置外观与名称。「清除全部本地记录与音频」不清除语言、形象等设置。
- 伙伴文案只反映记录运行状态，不从指标改变为悲伤、焦虑等未经确认的情绪形象。

## 4. 观察、触发与 Watch F03–F05

1. 用户阅读本次录音范围、在场他人知情、无预录、本地保留和后台限制后，主动开启观察。
2. 权限拒绝 / 不可用 / 档案不可写时不打开麦克风。开始请求与转写重试先取得任务占用，避免重复点击和异步重入。
3. 基线使用过去180秒至少5个新鲜有效样本的中位数，当前样本不参与其自身比较。
4. 小幅候选：绝对变化至少5 bpm，且相对变化至少5%，上升下降均可；大幅候选：至少20 bpm，且至少25%。两路冷却独立，均为30秒。
5. 有效心率30–240 bpm；拒绝无效、倒序、过旧和明显未来数据。触发需事件延迟不超过15秒，观察前的数据不启动录音；跨手机 / Watch 同一事件去重。
6. 手机需在前台、保护数据可用、观察有效且没有其他录音 / 转写。后台或繁忙时可保留重要事件及缺失原因，不补录过去声音。
7. 已有录音会话时，重要事件关联同一所有者；包括暂停期间到达的重要标记，但空档没有音频，不能把后来片段冒充它。
8. Watch 只在用户主动开始的真实步行会话中提供较密心率。结束后保存运动；不能通过虚假全天运动绕过系统限制。断连事件可排队，延迟后到达不补录。

## 5. 录音时长、中断恢复与转写 F06–F08

### 5.1 时长与存储

- 默认60分钟；最大1440分钟（24小时），最小1分钟；预设15/30分钟、1/2/4/8/12/24小时，也可自定义小时 / 分钟。
- 时限从实际开始录音计时，**包含中断等待时间**。例如上限60分钟，录20分钟后通话10分钟，最多再录约30分钟。续录不重置时限；超时、主动结束或结束观察后不能恢复同一次会话。
- 上限在观察 / 录音 / 转写 / 授权中不能修改。可随时结束；24小时是设置上限，不能保证系统、空间与电量允许持续运行到上限。
- AAC 单声道44.1kHz，目标64kbps；1小时约29MB，24小时约0.7GB，另有转写临时空间。长时间录音、亮屏和识别会增加耗电、温度与等待。
- 默认可在观察期间保持屏幕唤醒；用户可关闭。用户锁屏仍须尊重，未添加后台常驻录音能力。

### 5.2 恢复条件与状态

| 情况 | 当下处理 | 恢复方式 |
| --- | --- | --- |
| 来电 / 系统音频独占 | 暂停，完成并保存实际片段 | 收到结束通知且系统 `shouldResume` 允许，同时前台、解锁、可写、未到期时尝试一次 |
| 来电结束未给出 `shouldResume` | 保持暂停 | 用户点击「继续录音」尝试激活音频；系统仍独占时失败并保留暂停 |
| 应用失去前台 / 锁屏 | 暂停；保护数据锁定时档案待写保留内存 | 回到前台且解锁后尝试；若已有更严格的手动恢复要求，不被前台变化覆盖 |
| 音乐开始 | 使用允许混音的音频会话，系统允许时可共存 | 若仍触发独占中断，采用来电的恢复规则 |
| 耳机 / 音频设备断开 | 暂停，展示原因 | 用户确认录音环境后手动继续，避免自动切换拾音场景 |
| 音频服务重置 / 激活失败 / 编码失败 | 保留可用片段，保持暂停 | 手动尝试继续或结束转写，不反复自动抢占音频 |
| 达到时限 / 用户结束 | 关闭麦克风，合并处理已录片段 | 不可续录本次；观察仍开时，之后新事件可进入新会话 |
| 磁盘错误 | 停止采集并保护原档案 | 报错，不继续开麦 |
| 进程终止 / 系统杀进程 / 重启 | 下次启动将未完成任务标记中断 | 不自动开启麦克风；原音频可手动重试本地转写 |

顶部持续显示正在录音 / 暂停、当前时限、原因、进度、「继续录音」与「结束并转写」。等待恢复仍占用本次任务，不能同时启动第二个麦克风。自动恢复失败后转为手动，不定时无限重试。

### 5.3 多片段与时间对齐

每次续录创建新文件，保存 `recordingParts`：文件名、实际开始时间、最终文件时长对应的结束时间（文件暂不可读时采用录音器报告时长；播放仍校验真实文件范围）。第一片段保留旧 `audioName` 兼容字段；中断空档不拼接成假连续声音。

- 播放标记：找到包含事件时间的实际片段，偏移为 `事件时间 - 片段开始时间`。空档和超出范围明确提示无对应音频。
- 转写：各文件内部按45秒导出临时片段后离线识别；合并偏移为 `该文件开始 - 整次开始 + 文件内分段偏移 + 词偏移`。
- 详情可播放每个真实片段；标记跳转不会顺带声称恢复未录制的对话。目前不提供跨文件无缝连续播放。
- 每个录音文件转写结束后保存已有文字。单一超长文件处理中强制终止可能需要重新转写该文件；不是后台可靠作业队列。
- 部分成功状态保留成功文字及失败数；识别不可用时原音频仍保留，可重试。无网络 / 本地模型缺失时不切换到云端。
- 临时 `chunk-*.m4a` 处理后清理，重启时清理残留；原始音频不自动删除。

## 6. 心率曲线、事件详情与反馈 F09–F10、F14–F15

- 记录实际心率与当时可用基线；普通点约至少5秒间隔，事件关键点保留。图表保留首尾和极值抽样，最多约500个绘图点；孤立点显示，超过90秒无数据时断开。
- 橙点：大幅心率变化；紫点：综合显著度至少65且可用权重覆盖至少80%。点击点附近进入详情，显示触发时健康数据快照。
- 转写先展示该标记前后20秒内的实际文字，可展开完整转写；显示时间片段与谨慎的用词线索。没有预录，所以初次触发前的声音不可用。
- 用词线索仅覆盖保守的压力、愉快、疲劳词，处理部分中英文否定和词边界；复杂否定、讽刺和上下文仍需本人判断。
- 可选本人反馈：愉快、紧张、平静、身体累、说不清、只是运动；不回答保留未知。
- 日期按设备当前日历筛选。跨午夜的重要事件可引用前一日开始的录音；当日没有新标记时不自动将整段录音拆成额外事件。
- 删除关联标记不删除共享声音；删除所有者会删除所有实际片段与关联标记。记录有变化时旧摘要失效，生成中的旧证据结果也会被丢弃。

## 7. 健康指标、事件算法与睡眠 F11–F13

### 7.1 HealthKit 输入及有效期

| 指标 | 接口 / 单位 | 用作事件情境的最大年龄 | 说明 |
| --- | --- | --- | --- |
| 心率 | heartRate / bpm | 45秒；录音触发15秒 | 必要触发信号，非全天实时保证 |
| 血氧 | oxygenSaturation / % | 2小时 | HealthKit比例值转换为百分数；设备/地区可能无数据 |
| HRV | heartRateVariabilitySDNN / ms | 6小时 | 机会式采样，不等同于即时压力 |
| 步数 | stepCount / 近5分钟累计 | 聚合刷新后2分钟 | 使用HealthKit累计统计，不把无数据变为0 |
| 活动能量 | activeEnergyBurned / 近5分钟kcal | 聚合刷新后2分钟 | 与步数一起仅提供运动情境 |
| 环境音暴露 | environmentalAudioExposure / dBA | 30分钟 | Apple健康历史暴露记录，不启动持续监听 |
| 耳机音暴露 | headphoneAudioExposure / dBA | 30分钟 | 暴露估计，不是系统音量滑块或持续实时分贝 |
| 睡眠估算分 | sleepAnalysis派生 / 0–100 | 36小时 | 本地公式，非Apple官方睡眠评分 |
| 睡眠腕温 | appleSleepingWristTemperature / °C | 36小时 | 睡眠样本，非随时可采的体温 |

健康权限由用户逐项选择，读取不到不能区分为拒绝还是没有样本。所有类型都显示最新可读时间和来源，缺失/过期保持未知。

每次读取离散指标最多400条、睡眠最多6000条，最长14天；上下文约每分钟刷新，可手动请求。每类持久化最多500条。样本上限可能造成历史覆盖不足，此时不建立个人基线。

近5分钟步数/能量的严格起点统计可能低估跨窗口长样本，仅作为运动线索。新鲜聚合时间表示窗口结束时间，不代表同一时刻传感器连续测量。

### 7.2 事件显著度算法 context-1

事件显著度用于排序与标记，不是健康总分、情绪标签、诊断或医学告警。没有辅助数据仍可按小幅心率规则录音；其他指标不能单独启动麦克风。

#### 个人偏离

离散指标使用前14天至少5个有数据日的每日中位数，再取跨日中位数与MAD，避免高频样本假装多天证据。

偏离归一化：`max(0, difference / max(noiseFloor, 3 × 1.4826 × MAD))`，并截断到0–1。

- 血氧和HRV使用相对个人中位数的降低幅度。
- 音暴露、腕温使用绝对偏离幅度。
- 噪声下限：血氧2个百分点、HRV10ms、声音10dBA、腕温0.2°C；只是工程参数，需个人实测校准。
- 没有足够个人基线时，该指标只展示，不参与偏离加权。
- 睡眠使用本地估算分的低值情境：`clamp((80-score)/50, 0, 1)`，不需要伪造其历史基线。

#### 加权

| 分量 | 权重 |
| --- | --- |
| 心率变化 `clamp(abs(delta)/max(20, baseline×25%),0,1)` | 0.60 |
| HRV偏离 | 0.12 |
| 血氧偏离 | 0.08 |
| 睡眠情境 | 0.07 |
| 环境音偏离 | 0.05 |
| 腕温偏离 | 0.05 |
| 耳机音偏离 | 0.03 |

只对真正可用分量求加权平均并乘100；显示有效权重覆盖。权重覆盖不是置信度。近5分钟步数至少20或活动能量至少2kcal时，心率分量乘0.65，标为“可能伴随活动”；仍保留录音，不断言运动就是原因。

阈值、权重和窗口未经临床验证，不可据此推断焦虑、愤怒、低氧疾病或心理状态。AI只解释已有事实与本人反馈，并保留未知。

### 7.3 本地睡眠估算

按中午分界归并夜间数据；优先有实际睡眠样本的Watch来源，否则使用其他有睡眠样本的来源。跨来源不相加。

同来源重叠睡眠区间取并集，扣除明确清醒交集。间隔超过2小时分开为不同睡眠会话，选主要会话；不足30分钟不评分，仅在床记录不产生睡眠分。

以8小时作为可解释的工程目标：

- 没有完整在床信息：`100 × min(实际睡眠/8小时,1)`。
- 在床信息足够：`100 × (0.75 × 时长达成率 + 0.25 × 睡眠/在床时长)`。

这是时长/效率估算，不能评价疾病、睡眠阶段准确性或替代专业评估；主睡眠分段和跨时区行为需真机数据进一步验证。

## 8. 每日回顾、双语与模拟 F16–F18

- 每日摘要只使用当天事件 / 重要标记附近20秒的实际文字与本人反馈，保持事实、本人感受、待验证解释的区别；无音频事件不补造谈话。完整音频与转写仍留本地。
- Apple FoundationModels 仅在 Xcode 26+ 编译、运行设备 / 地区支持且模型就绪时可用；多批整理后汇总，输入包含事件显著度与活动情境，不能将其变成情绪证明。模型失败报错，可主动使用规则摘要。
- 规则摘要明确标注非大模型。摘要列出对应事件依据；数据或语言变化后需重新生成，原始转写不自动翻译。
- 系统 / 简体中文 / English 选择保存并同步可连接 Watch；Watch 可独立选择，下一次手机同步可能覆盖。系统偏好无法匹配时回退英文。
- 新录音保存 zh-CN / en-US 对应识别语言；重试旧录音沿用原语言，早期没有语言字段的录音按中文。进行中的授权、录音、转写和摘要限制手机语言切换。
- App 界面与系统权限弹窗语言可能不同：系统弹窗由系统或单独 App 语言控制。
- 模拟模式可体验事件、曲线、指标、感受与摘要；明确模拟，和真实数据分离；不生成可冒充真实录音的文件、不连接传感器或打开麦克风。

## 9. 档案、隐私与异常保护 F19

| 数据 | 当前保留方式 |
| --- | --- |
| 音频 / 转写 / 事件 / 摘要 | 手机应用私有目录；用户主动删除，暂无自动过期 |
| 心率曲线 | 近7天、最多60000点；先达到哪个限制即按哪个清理 |
| 辅助指标 | 最近14天，每种最多500条 |
| 形象 / 语言 / 时长等设置 | 本机偏好，无应用提供的跨设备形象同步 |
| 转写临时文件 | 处理结束删除，初始化清理意外残留 |

应用主动创建的档案目录使用 complete 文件保护、原子写入并排除该目录系统备份；并不承诺系统对所有偏好、设备迁移或外部手动备份的行为。无账号、广告或分析 SDK；无应用网络上传健康档案接口。

曲线常规写盘约每分钟一次，事件、暂停、结束主动写盘。锁屏期间不可写时待写快照留内存，解锁后重试；进程被终止则尚未写盘的数据可能丢失。冷启动保护数据不可读时等待解锁，不把读取失败当空档案。损坏 JSON / 不支持版本 / 磁盘错误禁止覆盖原档案并停止采集。

当前 JSON 版本仍为1，新数组通过缺省解码、新 Episode 字段通过可选值兼容旧数据；旧单一音频时间轴仍可播放 / 转写。

删除不会修改 Apple 健康中的源数据。当前未提供导出、备份恢复；卸载可能丢失全部本地记录。现场录音应由用户确保适合当前场景且在场人员知情。

## 10. 工程验证与 review 约定 F20

- Linux：`./scripts/check.sh` 运行核心 XCTest、双语资源审计、实际 AppModel 配合平台替身的流程场景、iOS / Watch 语法检查与差异空白检查。
- 平台替身场景验证应用状态机和任务占用，**不验证 Apple SDK 类型、音频路由、传感器、文件保护或真机系统通知**。
- Mac：`./scripts/setup-mac.sh` 显示5阶段与15秒运行心跳，保存 `.build-logs` 原生日志；失败保留原始退出码并摘取第一处错误。阶段进度不伪装成编译百分比。
- 已提交 XcodeGen 定义、Xcode 工程、Mac CI 配置；私有仓库 CI 结果以 GitHub 上的实际记录为准。此前旧版用户确认原生构建成功，不代表本版原生已经通过。
- 本版自动化结果记录在 [Validation.md](Validation.md)；Mac / 真机步骤与未执行项在 [Device_Test_Plan.md](Device_Test_Plan.md)。

每个新增 / 修改功能提交必须更新：功能编号与行为、数据与生命周期影响、异常 / 缺失处理、验证结果、未验证边界。不把未实现的计划写成可用功能。
