# v0.4：可配置长录音、心率曲线与多指标情境

日期：2026-10-27。本文为当前实现规格，替代 v0.3 的固定30秒和大幅波动才开始录音的默认规则。所有规则均为工程启发式，尚未进行临床或情绪识别准确率验证。

## 1. 录音与转写

- 设置页可选最长录音1–180分钟，默认60分钟；正在观察或处理录音时不可修改本次上限。
- 用户授权并开启观察、手机前台、保护数据可写、新鲜心率事件到达且无其他录音/转写任务时，才启动麦克风。无预录。
- 可随时停止。时长是上限，不承诺一定持续到上限：来电、锁屏、切后台、存储错误和系统中断仍可能结束录音。
- 默认提供“观察期间保持屏幕唤醒”，用户可关闭；手动锁屏始终尊重。长时间亮屏和音频处理会增加耗电。
- AAC单声道，目标64kbps；一小时约29MB，仅作容量估算，实际以文件为准。无云上传，文件保护与备份排除保持不变。
- 停止后将录音按45秒导出为本地临时片段，逐段离线识别；一小时约80段。合并时将片段时间偏移加回原始录音时间轴。
- 界面显示已处理分段数。一部分失败时保留成功文字和“部分转写”状态，显示失败段数；原始音频仍可播放并重试。
- 临时片段在处理后删除，应用下次初始化时清理上次意外终止留下的 `chunk-*.m4a`。识别语言保留原录音设置。
- 转写属于耗时任务，不能保证实时完成。繁忙期间记录新的重要事件，但不同时开启另一录音；其无音频状态必须真实展示。

## 2. 心率触发与重要标记

基线为过去180秒至少5个新鲜有效样本的中位数，当前样本不参与其自身的比较。普通心率采样可能太稀疏而无法建立基线；不会填入模拟值。

- 小幅触发：相对基线的绝对变化至少5次/分，且相对变化至少5%，方向可升可降。
- 大幅变化：绝对变化至少20次/分，且相对变化至少25%。
- 两路独立检测器的冷却均为30秒，因此刚发生小幅触发，也能捕捉随后出现的大幅变化。
- 开启观察之前、明显未来、无效或过旧的样本不能启动录音。延迟超过15秒的事件不补录；跨手机/Watch的同一事件去重。
- 多指标显著度达到65且有效指标权重覆盖至少80%时，也可列为重要标记，但必须先满足心率候选条件。
- 若已有录音，重要事件保存 `linkedRecordingID` 指向原录音，计算其相对开始时间；不复制音频，不重复开麦克风。
- 曲线中橙点为大幅心率变化，紫点为多指标重要事件。点击进入详情，播放从相应偏移开始；超出真实文件时长时明确报错。
- 删除标记不会删除共享音频；删除录音所有者会连同关联标记删除，避免悬空引用。

## 3. 曲线与持久化

保存实际心率样本及当时可用的近期基线。普通曲线点最小间隔约5秒，事件关键点强制保留。最多保留近7天和60000点，以先到的限制为准。

渲染时按桶保留首尾与极值，最多约500点，事件点另行叠加；超过90秒的采样缺口断开。孤立样本也以小点显示，不用连线伪造持续采样。

曲线常规写盘最多约每分钟一次，事件与结束时主动保存。最近尚未写盘的点在进程异常终止时可能丢失；锁屏待写数据仍只在内存中暂存。事件历史可比曲线保留得更久，旧事件可能没有完整曲线。

旧版JSON档案保持版本1，新增字段使用可选值或 `decodeIfPresent`；缺少曲线/指标数组时正常加载为空，不清空已有事件与音频。

## 4. HealthKit 输入及有效期

| 指标 | 接口 / 单位 | 用作事件情境的最大年龄 | 说明 |
| --- | --- | --- | --- |
| 心率 | heartRate / bpm | 45秒；录音触发15秒 | 必要触发信号，非全天实时保证 |
| 血氧 | oxygenSaturation / % | 2小时 | HealthKit比例值转换为百分数；设备/地区可能无数据 |
| HRV | heartRateVariabilitySDNN / ms | 6小时 | 机会式采样，不等同于即时压力 |
| 步数 | stepCount / 近5分钟累计 | 聚合刷新后2分钟 | 使用HealthKit累计统计，不把无数据变为0 |
| 活动能量 | activeEnergyBurned / 近5分钟kcal | 聚合刷新后2分钟 | 与步数一起仅提供运动情境 |
| 环境音暴露 | environmentalAudioExposure / dBA | 30分钟 | Apple健康历史暴露记录，不启动持续监听 |
| 耳机音暴露 | headphoneAudioExposure / dBA | 30分钟 | 暴露估计，不是系统音量滑块或持续实时分贝 |
| 睡眠估算分 | sleepAnalysis派生 / 0–100 | 36小时 | 本地公式，非Apple官方睡眠评分 |
| 睡眠腕温 | appleSleepingWristTemperature / °C | 36小时 | 睡眠样本，非随时可采的体温 |

健康权限由用户逐项选择，读取不到不能区分为拒绝还是没有样本。所有类型都显示最新可读时间和来源，缺失/过期保持未知。

每次读取离散指标最多400条、睡眠最多6000条，最长14天；上下文约每分钟刷新，可手动请求。每类持久化最多500条。样本上限可能造成历史覆盖不足，此时不建立个人基线。

近5分钟步数/能量的严格起点统计可能低估跨窗口长样本，仅作为运动线索。新鲜聚合时间表示窗口结束时间，不代表同一时刻传感器连续测量。

## 5. 事件显著度算法 context-1

事件显著度用于排序与标记，不是健康总分、情绪标签、诊断或医学告警。没有辅助数据仍可按小幅心率规则录音；其他指标不能单独启动麦克风。

### 5.1 个人偏离

离散指标使用前14天至少5个有数据日的每日中位数，再取跨日中位数与MAD，避免高频样本假装多天证据。

偏离归一化：`max(0, difference / max(noiseFloor, 3 × 1.4826 × MAD))`，并截断到0–1。

- 血氧和HRV使用相对个人中位数的降低幅度。
- 音暴露、腕温使用绝对偏离幅度。
- 噪声下限：血氧2个百分点、HRV10ms、声音10dBA、腕温0.2°C；只是工程参数，需个人实测校准。
- 没有足够个人基线时，该指标只展示，不参与偏离加权。
- 睡眠使用本地估算分的低值情境：`clamp((80-score)/50, 0, 1)`，不需要伪造其历史基线。

### 5.2 加权

| 分量 | 权重 |
| --- | --- |
| 心率变化 `clamp(abs(delta)/max(20, baseline×25%),0,1)` | 0.60 |
| HRV偏离 | 0.12 |
| 血氧偏离 | 0.08 |
| 睡眠情境 | 0.07 |
| 环境音偏离 | 0.05 |
| 腕温偏离 | 0.05 |
| 耳机音偏离 | 0.03 |

只对真正可用分量求加权平均并乘100；显示有效权重覆盖。权重覆盖不是置信度。近5分钟步数至少20或活动能量至少2kcal时，心率分量乘0.65，标为“可能伴随活动”；仍保留录音，不断言运动就是原因。

阈值、权重和窗口未经临床验证，不可据此推断焦虑、愤怒、低氧疾病或心理状态。AI只解释已有事实与本人反馈，并保留未知。

## 6. 本地睡眠估算

按中午分界归并夜间数据；优先有实际睡眠样本的Watch来源，否则使用其他有睡眠样本的来源。跨来源不相加。

同来源重叠睡眠区间取并集，扣除明确清醒交集。间隔超过2小时分开为不同睡眠会话，选主要会话；不足30分钟不评分，仅在床记录不产生睡眠分。

以8小时作为可解释的工程目标：

- 没有完整在床信息：`100 × min(实际睡眠/8小时,1)`。
- 在床信息足够：`100 × (0.75 × 时长达成率 + 0.25 × 睡眠/在床时长)`。

这是时长/效率估算，不能评价疾病、睡眠阶段准确性或替代专业评估；主睡眠分段和跨时区行为需真机数据进一步验证。

## 7. 每日摘要与隐私

长录音完整转写保留本地；每日摘要只选每个触发/重要标记附近前后20秒的实际可用文字。没有预录，所以前文不足时保留缺失。

同一文件的多个标记按不同偏移提取文字；跨午夜的标记能引用前一日开始的录音。AI输入包含非医学显著度和运动情境，不能把这些分数解释成情绪证明。没有对应片段的事件明确缺失，不改用整段无关谈话补齐。

中英文UI、权限说明、转写语言持久化和模型降级策略保持有效。长录音原文件需用户主动清理；未提供备份恢复。
