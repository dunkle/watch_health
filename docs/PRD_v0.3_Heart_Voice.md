# v0.3：心率事件驱动的语音回顾

日期：2026-10-26。此文是当前实现目标，优先于 v0.2 中更广泛的首版范围。

## 用户目标

基于 Apple 传感器数据，在心率明显波动时录制短语音、本地转写、定位相关文字，由 AI 整理上下文形成每日摘要，提供完整 iPhone 与 Watch 界面。

## 可实现边界

- 心率波动不等于情绪变化。系统记录候选事件，词语线索只显示“可能涉及”，感受由本人确认。
- 不预先录音就没有事件前谈话；本版本只捕获事件后的最多30秒。转写分段时间相对于真正的录音开始时间，不相对于识别完成时间。
- 普通状态下 Apple Watch 的心率数据可能稀疏、延迟。不得承诺全天连续监控。
- 用户可在真实步行时开启 Watch 步行会话，获得运动期间心率并保存真实运动记录。不得为了后台运行伪造全天运动。
- iPhone 必须已授权、开启本次观察且在前台才能自动尝试录音。锁屏、后台、过期事件、权限或设备问题会阻止录音，并记录原因；不会冒充捕获了当时语音。
- 本版本手表只采集心率和发送事件，不在手表录音。手机不在附近时没有可靠语音上下文。
- 本地语音识别不支持当前语言或模型时明确失败，不上传云端。
- Apple 端侧模型需要合适 SDK、设备、系统、地区、语言和模型就绪状态；运行时不可用则标注规则摘要。模型输出不是确认事实。

## 检测规则

使用过去180秒内至少5个有效样本的中位数，与当前样本比较。变化绝对值至少20次/分且相对变化至少25%才生成事件，事件冷却180秒。仅接收30–240次/分的有限值，拒绝倒序、过旧和明显来自未来的样本。阈值是可校准工程参数，不是医学标准。

手机接受 Watch 或本机 HealthKit 的候选，跨来源同一3分钟窗口去重。触发超过15秒未到达则不开始录音。开始观察之前的数据不触发录音。迟到事件的手机传输时间不是其发生时间。

## 页面

1. 现在：观察状态、最近新鲜心率、开始/结束、今日计数、最近片段。
2. 记录：按日期回看事件、基线与触发心率、完整转写、附近时间窗文字、原始音频播放、本人确认、重试和删除。
3. 每日摘要：日期选择、本地模型/规则引擎标识、证据链接、生成时间、生成内容待核对说明。
4. 设置：运行边界、权限入口、模拟模式、数据清除与当前不支持备份的说明。
5. Watch：明确的真实步行开始/结束、心率、事件排队状态与手机录音条件。

视觉采用暖白底、深绿文字、鼠尾草绿主色、陶土色心率提示。使用原生布局、SF Symbols 和 Apple Charts，无第三方 UI 素材或云服务依赖。

## 隐私与存储

- 每次观察前明确告知触发录音，提醒在场他人知情同意。
- 应用未开启观察时不监听；录音时应用有醒目标识，系统也提供麦克风状态。
- 音频、JSON档案、转写和摘要保存在应用支持目录，设置文件保护并排除该目录的系统备份。无云接口、云模型或分析SDK。
- 原始音频不自动清理，用户可逐条删除或整体清除。未实现备份与恢复，卸载可能丢失全部记录。
- 结束观察不删除已有记录；删除应用记录不修改 HealthKit 的源心率。
- 丢失或损坏档案时不覆盖原文件，不假装空库继续采集。

## 验收状态约定

Linux 单元测试与 Swift 语法检查不等于 Apple 平台编译，更不等于实时传感器、录音和后台真机验证。必须按 Device_Test_Plan.md 完成实机演练后才能称该设备上的实时闭环已完成。

后续再验证：后台可行的用户主动音频会话、手机与手表端录音取舍、上下文窗口长度、不同活动的误触发、设备耗电、原始音频保留策略和备份恢复。未经验证前不把它们计入当前能力。
